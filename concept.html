TaskChute Journal / Concept

時間ではなく「どんな日を積み重ねているか」を可視化する

仕事もプライベートも分断せず、すべての予定・プロジェクト・タスクを1つの道具で管理する。日々の実行率(着手率)を上げ、実行が自動で記録され、AIフィードバックの改善ループを回す——単一ユーザー(K)専用に最適化した、ローカルファーストな自己ダッシュボード。ホーム画面はタスク一覧ではなく操縦席として組織される。

基盤: 12 Week Year × タスクシュート『先送り0』 × PMBOK 2026-08-23 / 正本: taskchute-notes/CONCEPT.md

01理論的基盤 — 3本柱と機能の対応

12 Week Year

12週間を1年として実行する

  • 84日サイクル — twelveWeekStartDate を持つ Project がサイクル目標 実装済み
  • 第13週レビュー — cycleビューで締め、「新しい12週を今日から」で次へ接続
  • 週次コミット — 候補ブロック自動コミット・達成率目標(既定85)
  • 日・週・84日の3スケールは都度計算、永続化はレビューメモだけ

タスクシュート『先送り0』

1分着手・ログ先行・ルーチン化

  • 1分着手 — 主指標は完了率でなく着手率。MITは1日3件まで。着手の瞬間だけ祝う「着手ジュース」 実装済み
  • 先送りゼロ — 繰り越しパネル+3回で一呼吸置く「儀式」+migratedTo で二重繰越防止
  • ログ先行 — Block は予定(planned)と実績(actual)を分離して記録
  • ルーチン化 — 繰り返しルールから冪等に実体化。保護属性・縮退版・アンカー・チェーン

PMBOK

プロジェクトマネジメント

  • WBS — Project → Task 最大3階層 → 日別Block 実装済み
  • バッファ管理 — 見積超過を「1日バッファ」1本に集約し残量%のみ表示。過積載も自動解消しない
  • 状態遷移 — active / paused / completed / archived / cancelled。中断・中止は進捗分母から除外

02実行ループ — 計画から改善までを1つの系にする

03設計原則 — このアプリ固有の憲法

P1

静かな道具

通知サブシステムはv38で削除。締切・リマインド・催促・Web Pushを持たない。

P2

裁かない計器

実行率を自己評価の点数にしない。保護系ルーティンは%でなく連続欠落日数で見せ、1日の欠落では警告しない(Never miss twice)。

P3

保護属性・縮退版

運動・睡眠・内省・家族時間は生産性で裁かないメンテナンス工程。崩れた日は最小構成(縮退版)でも継続扱い。

P4

搬送は自動化、判断は人に残す

転記・プリフィル・提案は自動化するが、採否は常に人間。AIループ全体を貫く最重要原則。

P5

下書き承認フロー

配置提案は非永続の下書きに仮置きし、「確定して登録」を押すまでBlockにならない。

P6

ローカルファースト・データ主権

localStorage主+private GitHub同期。サーバー・アカウント・課金なし。曖昧なら上書きせず止まる(fail-close)。

P7

物理削除しない・後方互換を壊さない

論理削除のみ。stateスキーマ変更は normalizeState() のデフォルト補完だけ。

P8

実行時依存ゼロ・ビルドなし

フレームワーク不使用、単一状態+全再描画。src/core(純粋関数)/features/state/storage へ境界分割進行中。

04AIフィードバックの搬送構成 — アプリはAIを呼ばない

現状記録(採否・修正・実績 = aiScheduleHistory)は貯まっているが、次回提案への自動注入はv60で廃止。ループは完全には閉じていない 実装済み
構想 v62バッチが app-state.json を読んで AIプラン_日付.json を生成し、朝プランが下書き採用(オフライン時は決定論フォールバック) 構想
構想 v64採否履歴・見積乖離・時間帯別成功率を学習シグナルとして集計し、AIプラン・コーチングのプロンプトへ注入。無修正採用率を週次追跡 構想

05やらないこと(非目標)

多人数SaaS・汎用PMツール化 — 単一ユーザー最適化を崩さない。同期は「ファイル丸ごと新しい方が勝つ」のみ

✕

ネイティブiOSアプリ化 — Safariホーム画面PWA+ビルドなし・依存最小を維持

✕

アプリ内AI直接呼び出し — APIキーを持たない。AIはバッチ→GitHub→fetchのみ

✕

通知・催促・Web Push — v38削除以後、復活させない。外部通知もアプリ状態を書き換えない

✕

ストリーク罰・派手なゲーミフィケーション — 継続可視化はオプトイン+自己ベスト保持+静かなリセットの型に限る

✕
